# Battles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Live best-of-5 stat duels between friends, using a saved 5-card deck, with a W-L-D record per player.

**Architecture:** All rules live in a new `game/battles.py` (like `trades.py`/`friends.py`): it is the only
place that mutates battles, always under `select_for_update`. There is no background worker: every read
or pick first calls `advance()`, which auto-plays overdue rounds. Views are thin; the battle page is plain
JS (`battle.js`) that polls a JSON state endpoint every 1.5 s and posts picks.

**Tech Stack:** Django, Postgres 17, plain JS/CSS, Django i18n. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-24-battles-design.md`

## Global Constraints

- No new Python or JS dependency. No websockets/Channels.
- Constants live at the top of `game/battles.py`: `DECK_SIZE = 5`, `ROUNDS = 5`,
  `RARITY_CAP = {Rarity.LEGENDARY: 1, Rarity.EPIC: 2}`, `PICK_TIME = timedelta(seconds=30)`,
  `REVEAL_TIME = timedelta(seconds=3)`, `CHALLENGE_TTL = timedelta(minutes=2)`,
  `STATS = ("subscriber_count", "post_count", "event_count")`.
- Friends only (`friends.are_friends`). No stakes: battles never touch `Pull` rows. The trade code is **not** modified.
- Every user-facing string is wrapped (`gettext_lazy` / `{% trans %}`). Every task that adds strings ends by running
  `makemessages -l fr`, filling **every** new `msgstr` in `game/locale/fr/LC_MESSAGES/django.po`, running
  `compilemessages`, and committing both `.po` and `.mo`. JS strings go through `data-msg-*` attributes (like `pack.js`).
  Stat labels reuse the existing msgids `"Subs"`, `"Posts"`, `"Events"`.
- Functions that depend on time take `now=None` (defaults to `timezone.now()`), like `packs.open_pack`, so tests pass explicit times.
- Tests: `docker compose exec web python manage.py test game` (Postgres required).
- Work on a new branch `feat/battles` created from `feat/trades` (battles reuse friends and the trade card-picker styles).

## Review Focus

1. **Both players close the tab mid-battle.** Nobody polls, so the battle stays `active` and both are "busy" forever.
   Expected: anything that checks busyness (`challenge`, hub page) first runs `advance()` on the player's active battle, which finishes it.
   Test added to Task 3 (`test_abandoned_battle_finishes_on_next_challenge`).
2. **Double-submit, replay or tampered picks.** Covers: a second pick in the same round, a card already played, a card not in your deck, a non-numeric id, and a pick after the deadline already auto-played the round.
   Expected: a `BattleError`, and state unchanged. Tests in Task 3.
3. **Opponent card leak in the state JSON.** This includes the current pick before both picks are in, and unplayed deck cards via the hand, the history or the markup.
   Expected: opponent card names/ids appear only once revealed. Tests in Task 4.
4. **Crossing challenges.** For example, A→B is pending and C→B is sent, or B, with an incoming challenge, tries to challenge D.
   Expected: "busy" error, so each player is in at most one pending-or-active battle. `challenge()` locks both `User` rows in pk order.
   Tests in Task 2.
5. **Saved deck goes stale** (a card traded away, or a re-import re-ranks a card past the rarity cap).
   Expected: `challenge()`/`accept_challenge()` refuse with the deck problem, and a stale challenge is deleted at accept time.
   Tests in Task 2.

### Task 3: Playing rounds, timeouts, end of battle, record

**Files:** Modify `game/battles.py`, `game/tests/test_battles.py`

**Interfaces:**
- Consumes: Task 2.
- Produces:
  - `play_card(user, battle_id, card_id: str, now=None) -> Battle`
  - `advance(battle, now=None) -> None`: the caller holds the row lock, or `advance` takes it itself.
  - `scores(battle) -> tuple[int, int]`: (challenger, opponent) over resolved rounds.
  - `remaining_cards(battle, side: str) -> list[str]`: card ids in that side's snapshot not yet played. `side` is `"challenger"` or `"opponent"`.
  - `record(user) -> dict` with keys `"wins"`, `"losses"`, `"draws"`.

**Rules to implement (from the spec):**
- **Resolution.** A round resolves when both cards are set. Compare `deck[str(card_id)][round.stat]` from each side's snapshot: the higher value scores 1, and equal values score nothing (a drawn round).
- **After a round at time `t`:** let `left = ROUNDS - number`.
  - If `abs(score diff) > left` or `left == 0`, set FINISHED and `winner` (or `None` on equal scores).
  - Otherwise create round `number+1` with a fresh `random.choice(STATS)` (repeats allowed) and `deadline = t + REVEAL_TIME + PICK_TIME`.
  - `t` is `now` for a second pick, and the round's `deadline` for a timeout.
- **`advance`:** while the battle is ACTIVE and the current round's `deadline <= now`, fill each missing side with `random.choice(remaining_cards(...))`, then resolve at `t = deadline`. It loops, so several overdue rounds catch up in one call.
- **`play_card`:**
  - Lock the battle and call `advance(now)` first.
  - Then require ACTIVE, the user is a participant, no card yet for their side in the current round, and `card_id` is in `remaining_cards`. A late pick is rejected because `advance` already played that round.
  - Set the card and resolve if both are set.
  - Messages:
    - `"This battle is over."`
    - `"You already played this round."`
    - `"Pick a card from your deck that you haven't played yet."`
- **`record`:** one aggregate over FINISHED battles where the user is challenger or opponent.
